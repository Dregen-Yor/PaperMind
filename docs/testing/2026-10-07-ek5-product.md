# E-k5-hybrid 产品接入交付

分支：`feat/Ek5`。启动：仓库根目录运行 `npm run dev`。

## 已实现

- 正式论文问答仅使用 E-k5-hybrid：标题路径向量 + 标题路径/正文 BM25，等权 RRF（60），每篇取 top-5 叶子组，保留组完整原文及页码。与本次 PeerQA benchmark 的分组、排序和上下文有对照测试。
- 本地模型保持 `Xenova/bge-small-en-v1.5` q8、384 维，与本轮 benchmark 一致；没有换成 BGE-M3 embedding。
- 使用既有 SQLite index 表，版本 `ek5-product-v1`；旧索引首次使用自动迁移。完整成功后才覆盖，模型/版本/文本/向量损坏会触发重建；并发同篇构建合并，手动强制重建等待旧任务后再执行。
- 首次提问、重试、续写走相同检索入口。多论文上下文带论文标题，来源保留 paperId 与页码。划选问答和 /abstract 独立保留。
- 不再提供旧语义树检索开关或索引 LLM 选择。设置页展示模型状态、上下文上限和本地索引重建入口。旧语义树 API 仅为数据兼容保留，不参与正式检索。
- 修复实际启动发现的 WASM 路径问题：从应用 URL 定位 ort 资源，避免 Vite 将 ./ort 解析到依赖目录。

## 使用边界

第一次使用需要下载本地向量模型；后续使用 IndexedDB 缓存。模型不可用时明确报错，不自动切到 BM25、旧段落检索或全文。无文本层或无法定位章节的 PDF 给出提示，可改用划选文本提问。

正常检索没有旧版 4096-token 截断。产品为合并参考内容提供默认 120000 字符上限，可在设置中调整为 4000–1000000；超限会提示缩小范围，不截断组。这是字符资源保护，不是提供商 token 上限，历史与输出仍需预留空间。

保留产品原有多轮改写和回答提示词。因此单次检索算法与 bench 对齐，不表示完整多轮聊天与单题 benchmark 的提示词完全相同。缺失标题、非叶子节点独立引言等正文覆盖限制也保持本轮 E 的行为。

## 验证

- `npm run typecheck`：通过。
- `npm test`：82 个 Vitest 文件、954 项测试通过；branding 18 通过、1 项仅 Linux 工具可用时执行的检查跳过；benchmark launcher 4 项通过。
- `npx vite build`：前端、Electron main、preload 构建通过。
- `npm run dev`：Vite 与 Electron 窗口实际启动；真实 WASM 模型完成加载。
- 使用隔离临时用户目录执行真实 PDF 问答冒烟：PeerQA `egu/esd/14-1261-2023` PDF 解析、建 16 个叶子组及 16 个 384 维向量、选中 5 组完整原文、保存 5 个可跳转来源。生成请求使用本地模拟 SSE 响应，验证流式与落库，不发送付费请求；并非重新测量回答质量。

旧段落降级、旧语义树成为产品检索路径的断言已替换为 E-k5 独占、迁移、缓存、并发、模型失败、多论文、续写与预算测试；通用旧算法与 benchmark 测试保留。现有 QASPER/PeerQA 结果及冻结快照未修改。

- 生产构建 `file://` 窗口也已启动并完成上述问答冒烟。隔离新目录首次远程权重下载失败；为区分网络与打包问题，将已有同版本权重写入隔离测试缓存后，WASM 推理、PDF 索引和 top-5 来源均正常。真实用户首次下载仍依赖网络。
- 独立审查确认核心算法一致，发现的来源错配竞态已通过固定提问时论文 ID 快照修复，并新增回归测试。

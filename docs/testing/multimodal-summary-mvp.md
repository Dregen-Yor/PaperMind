# 多模态摘要 MVP 验证记录

## 使用入口

- 设置中选择支持图片输入的 OpenAI 兼容配置，本轮实际验证使用 deepseek-flash；保留配置的默认思考行为。
- PDF 导入成功后后台准备素材；阅读界面的摘要面板或聊天 /abstract 生成摘要。
- 网页首次打开并保存稳定快照时，一并保存视觉 PDF、准备素材；左侧保留网页预览，右侧沿用论文页的“网页问答 / 网页摘要”图标页签；切换保留问答草稿。历史快照缺少完整视觉副本时更新缓存。
- 生成任务在切换文档或路由后继续；可以主动停止、重新生成或继续被截断的摘要。完成结果和素材在本机保存。
- 摘要使用设计文档中的原始提示词，不强制改成中文。来源内容只作为待分析数据。

## 真实运行检查

### PDF 模型流程

在独立临时 Electron profile 和数据库中使用原 2412.19437v1.pdf 的第 7、10 页摘录，调用实际配置的 deepseek-flash。测试没有改动应用数据库或 PDF 原件。

共享产品代码完成页面渲染、模型素材定位、实际像素裁剪、SQLite 保存、再次视觉阅读和摘要生成。没有人工提前指定图片清单。结果：2 页输入，7 项素材，摘要选用 2 张原图，包含 LaTeX，未截断；素材准备与生成共约 48.51 秒。该耗时不代表完整 53 页论文。

视觉检查发现模型的部分定位框偏紧；实现增加图表边缘留白，公式采用整行宽度和上下留白，保留模型原框及实际 cropBbox。利用已有定位结果离线重新裁剪并检查全部 7 项素材，不额外调用模型。区域可能包含相邻正文，不宣称精确公式分割。

隐藏窗口真实运行暴露 PDF.js display intent 依赖 requestAnimationFrame 导致等待的问题；改用 print intent，并通过实际 Electron 页面渲染及回归测试。

### 网页视觉副本

使用 https://niutrans.github.io/RL-without-Tears/reader.html，在独立临时 profile 中采集。源页面约 101,505 个文字字符、23 张图片、154 处 KaTeX。

MHTML 约 62.4 MiB，超过既有 32 MiB 限制，且没有保存 10 个 KaTeX 字体资源，不能把该缓存当作完整视觉输入。最终策略是在在线原文资源已加载时直接保存屏幕样式 PDF；后续模型处理只读取保存的 PDF。

结果：58 页、3,566,527 字节，采集及已保存副本回读约 1,718 ms。关闭在线源窗口后仍能回读。检查页面 3、5、12，配图及求和、分数、上下标可见；文字检查覆盖末尾参考文献和项目地址。没有向付费模型提交整本网页书，因此不声称完成这份网页的真实模型摘要质量验收。

另用含固定高度滚动容器、100 段正文和 SVG 的本地测试页面，验证离线恢复路径得到 4 页 PDF，并包含首段、末段、最终标记及图注。MHTML 内脚本被禁用，改用同步受控 CDP 检查及主进程资源就绪轮询；不启用来源网页脚本或放开离线网络限制。

## 兼容与边界

- 新摘要不调用 Docling，也不要求其服务健康；旧 Docling 摘要与原图仍可读取。
- 素材、摘要和任务按原文版本绑定；修改原文或更新网页快照不复用旧坐标。
- 备份涵盖新素材、摘要、网页视觉 PDF；恢复前检查来源和素材完整性。删除来源级联删除其缓存与图片。
- 当前单篇最多 120 页、页面图像总计 48 MB；超限提前报错，不静默丢页。渲染页暂不做磁盘缓存，自动 PDF 准备串行执行以控制内存。
- 首次素材定位可能需要多次模型请求。进度按阶段显示，没有假定速度提升或推理百分比。
- 新网页视觉 PDF 是静态快照，动图固定为当时一帧；不会自动访问页面链接。
- 复杂网页若原貌、字体、图片或滚动内容无法完整采集，会明确报错。退出应用不会保持模型任务运行，已完成结果可重启查看。

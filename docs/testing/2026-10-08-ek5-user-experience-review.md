# feat/Ek5 用户体验反馈（2026-10-08）

当前判断：可以进行内部试用，但在中文提问与长论文的章节识别上还有明显的不稳定性。优先修证据质量，再完善引用和生成控制。本次没有修改产品代码。

## 范围与证据口径

- 分支：`feat/Ek5` 当前工作区构建，包含尚未提交的修改。
- 使用独立临时用户目录；仅复制当前对话模型配置。没有更改用户原文献库、对话或 API 配置。
- 回答模型：用户已配置的 `deepseek-flash`；输出上限不传。检索：产品默认 `Xenova/bge-small-en-v1.5@main#q8`，不是 benchmark 的 BGE-M3。
- 文档 A：*The effect of strong nonlinearity on wave-induced vertical mixing*，16 页，导入名 `Wave-Mixing-16pages.pdf`。
- 文档 B：*Few-shot Controllable Style Transfer for Low-Resource Multilingual Settings*，30 页，测试名 `Long-Paper-30pages.pdf`。
- **桌面实测**：导入 A、选择论文、新建对话、点击起始问题并发送真实请求、历史恢复、点击来源进入原文。桌面自动化一度出现状态延迟和 `noWindowsAvailable`，不将该现象归为产品缺陷。
- **补充链路实测**：复用产品 PDF 解析、E-k5 索引、检索、查询改写和回答提示构造函数，在 Node 中调用真实 API。覆盖中英文问题、具体事实、多轮指代、不存在的事实、30 页长文、两篇共同问答、外部选中文本、超预算、损坏 PDF。它验证回答链路，不等价于鼠标交互验证；Node 与浏览器的向量推理后端不同，不能把排序与时延视为完全一致。
- **代码确认**：停止生成、来源文案、模型准备进度和预算设置等界面能力。以下条目明确标注证据类型。
- 两篇论文不能代表整体准确率，本轮也不是替代 peerQA benchmark 的统计评估。

原始记录：`2026-10-08-ek5-ux-artifacts/desktop-first-question.json`、`pipeline-probes.json`。均不包含 API 密钥或服务地址。

## 优先处理列表

### F01 · P1 · 中文问题的证据召回弱，常混入无关章节

**证据：桌面实测 + 补充中英文对照。**

复现：导入文档 A，点击「概括核心贡献」，发送“这篇论文解决了什么问题？请概括它的核心贡献。”

桌面真实回答取回的 5 个来源是 Further discussions、Numerical test cases、References、Competing interests、Author contributions。其中后三个不适合支撑这个问题，且没有摘要与引言。回答可读，但省略了论文摘要强调的一些具体贡献。

文档 B 的同义概括问题，中文检索偏向第 9、14、25–26 页；英文检索能包含第 1 页摘要和第 7 页实验设置，回答明确给出“few-shot、七种语言、2–3 倍”等主要信息。中文版本更偏向附录表格数字。

建议：增加中文问题→英文论文的独立产品评测；对文献语言做查询适配，或比较真正支持跨语言的向量模型。不能直接把 BGE-M3 benchmark 的收益当作目前 bge-small-en 产品配置的收益。对贡献概括类问题补充摘要/引言覆盖策略；不要全局删除 References，文献追踪问题仍可能需要它。

验收：固定同义中英文问题集，比较相关章节召回、答案完整性、无关尾部章节占比与时延；本例核心概括不应主要依赖利益声明和作者贡献。

### F02 · P1 · 长论文的正文、作者名、表头被识别成章节

**证据：文档 B 真实解析与建索引 + 真实 API 回答；未完成 B 的桌面导入操作。**

复现：对 B 建产品 E-k5 索引并提问“请概括这篇论文的研究任务、方法、主要实验结果和局限，并给出对应页码。”

索引生成 75 个组，包括作者姓名/机构、印地语句子，以及 `Style Calibration to > G Ablation Studies > K Paraphrase Diversity > Model > Model > Model`。部分组只有十几到几十个字符。中文概括 Top-5 中出现重复路径的 Model 表头组和只有标题的片段。多论文回答甚至提示第二篇内容“零散”“题目与完整研究目标无法确定”，但实际 PDF 首页有完整标题和摘要。

建议：先完善章节结构质量门槛：排除作者区与重复表头、合并换行标题、约束层级、识别空壳章节。索引异常时明确提示，而不是只显示“已建立索引”。在 E 内完善分组，不应悄悄换成另一套检索方法。

验收：B 的章节树不再把作者信息和表格列名作为章节；摘要、核心方法与主实验能被完整定位；概括能说明“释义向量差分”这一核心方法，而非仅列出模型名称。

### F03 · P2 · 回答泄露内部证据编号，引用仍不够便于核查

**证据：真实多轮链路回答 + 来源展示代码；页码跳转已桌面验证。**

复现：A 首轮概括后问“它采用的是真正的非线性方法，还是弱非线性近似？请说明依据。”回答直接写出 `G0006`、`G0009`。用户不知道编号代表什么，也没有对应的可点击正文引用。

来源芯片是“章节名 + 页码”，正文的具体结论没有与之绑定。跨论文时，芯片 label 本身也不含论文名，两个同名章节不容易区分。

建议：将证据映射为稳定可点击的 `[1]`、`[2]`；多论文显示论文短名、章节和页码；点击定位并突出对应原文。不要把内部 group ID 当成面向用户的解释。

验收：输出不出现无法解释的内部编号；用户能从结论追到对应论文与段落。已有“第 6 页”来源点击确实打开第 6 页，应保留。

### F04 · P2 · 放开输出长度后缺少停止生成入口

**证据：界面组件与请求代码确认；未完成长回答中途取消的桌面测试。**

`ChatPanel.vue` 发送时使用 loading 按钮，没有停止按钮；请求使用超时信号，没有暴露用户取消接口。用户问错问题、发现选错论文或回答过长时，缺少直接中止方式。

建议：生成中将发送按钮变为“停止”，取消实际网络请求并保留已生成内容；与“超时”“失败”“用户停止”区分。无须重新引入默认输出 token 上限。

验收：流式回答开始后可立即停止，保留部分内容并可继续问下一题。

### F05 · P2 · 导入后主要按文件名辨认论文

**证据：桌面实测。**

导入 A 后列表显示 `Wave-Mixing-16pages` 和“作者信息待补充”，而 PDF 首页有完整标题和作者。真实科研文件名常为 DOI、下载编号或哈希，多篇阅读会更难辨认。

建议：优先读取可靠 PDF 元数据并结合首页标题/作者识别；显示提取结果供修正，失败时再保留文件名。回答和来源也应使用论文短标题。

验收：A 能显示真实标题、Paprota/Sulisz；原文件名仍可在详情中查看。

### F06 · P2 · 上下文预算出错后仍把技术判断交给用户

**证据：真实检索阶段触发 + 设置/报错文案代码确认；未验证失败卡点击重试。**

将参考内容上限设为 4000 字符，对 A 发送核心贡献问题，链路在生成前正确拒绝，提示减少论文、划选原文或提高上限。它避免了静默截断，是正确的保护；但用户不知道需要多少、提高到多少合适，也不知道聊天历史占用多少。

另一个针对 B 的概括问题仅取回 3574 字符，因此未触发该门槛。这说明短参考内容不代表证据充分，预算保护与召回质量需要分别观察。

建议：给出本次实际参考量、允许量和可操作的调整入口；有模型容量信息时估算完整请求（系统提示、历史、参考、回答余量）。预算单位在高级设置解释清楚，常规界面提供自动管理。

验收：超限卡说明实际量/上限，可直接调整后重试，原问题保留；不能仅把上限设得很高来隐藏问题。

### F07 · P3 · 模型与索引准备缺少可判断的进度

**证据：代码确认的体验建议；本轮没有复现模型下载失败。**

当前有“首次使用需要下载”“正在准备论文索引”等状态，但没有下载量、进度、当前论文/总数；模型错误也主要指导“联网后重试”。长文和多篇首次使用时，用户难以判断正在工作还是卡住。

建议：分开显示模型下载、解析、建索引、检索、生成阶段；提供下载进度和可重试错误原因。技术日志留在可展开详情。

验收：冷启动和慢网下能明确看出进展及失败位置；重试不需要用户重启应用。

### F08 · P3 · 单页来源文案与回答控制可再简化

**证据：桌面来源文案 + 代码体验建议。**

单页显示“第 6–6 页”“第 15–15 页”；长英文层级占用阅读器右侧空间。来源应以简短名称呈现，完整路径放悬浮提示。代码中流式输出会持续滚到底部，建议仅在用户原本靠近底部时跟随，让用户能读前文。

验收：单页显示“第 6 页”；用户向上阅读时不会被每次新 token 拉回底部。

## 性能观察与尚未完成的交互覆盖

桌面首轮 API 请求约 10.6 秒，另有约 7.7 秒的标题请求；这些是网络请求起止时间，不是首 token 或完整用户等待时间。补充链路的成功回答约 1.3–17.9 秒，暖态本地检索约 13–28 毫秒；一次多轮改写额外约 2.4 秒。仅为本机小样本，不构成性能 benchmark。

补充链路累计 10 次真实 API 请求（9 次回答、1 次改写），供应商返回的 usage 合计输入 37,751 token、输出 13,711 token；不含桌面首轮回答与标题请求。不能据此推断价格。

由于桌面控制工具的间歇性故障，本次不能声称已完成全部产品交互验收。长文 B/多论文的桌面操作、选文与笔记、异常卡重试、设置往返、删除/备份恢复、首次模型下载失败恢复仍需补测。补充链路实测不替代这些交互测试；删除和真实用户数据操作未执行。

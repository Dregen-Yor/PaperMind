# Web QA MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an independent webpage QA screen that sends a captured complete top-level DOM to the selected LLM and saves each snapshot and conversation locally.

**Architecture:** Extend the existing isolated `WebContentsView` with a guarded one-shot DOM capture. Store immutable HTML snapshots and QA messages in separate SQLite tables, then use the existing chat store's provider transport from a dedicated web-QA controller. Upgrade the current preview view to the PDF reader's split layout without changing PDF chat or Docling.

**Tech Stack:** Vue 3, TypeScript, Electron, `better-sqlite3`, Pinia, Vitest, Vue Test Utils.

**Spec:** `docs/superpowers/specs/2026-10-17-web-qa-mvp-design.md`

## Global Constraints

- Only HTTPS URLs may load in the embedded view; retain sandbox, context isolation, no remote preload, blocked permissions and blocked downloads.
- The captured context is the top-level doctype plus `document.documentElement.outerHTML` at the first question, capped at 8 MiB UTF-8 bytes with an explicit error and no truncation.
- A session always uses its immutable saved snapshot; every request includes the full HTML and completed prior QA turns. No Docling, PDF RAG, or silent context clipping.
- Desktop split starts 58%/42%, limits the left pane to 30%–75%, uses a 7px divider, 2% arrow-key steps, double-click reset to 58%, and switches to one pane at 800px.
- New database APIs must stay synchronized in schema, repository, IPC contract, preload and renderer declarations; backup/restore and clear must include web QA.

## Review Focus

- A redirect or SPA navigation races with DOM serialization: capture rejects instead of saving the wrong page (Task 1 test).
- The serialized page exceeds 8 MiB or contains non-ASCII text: enforce a byte limit without truncation (Task 1 test).
- A malformed imported web-QA row references a missing snapshot: reject before clearing existing data (Task 2 test).
- A cancelled or failed answer is retried: only completed turns enter the next LLM request (Task 3 test).
- The native webpage view is visible when the mobile QA pane is selected: hide or zero its bounds, preserving QA controls (Task 4 test).

```sql
CREATE TABLE IF NOT EXISTS web_snapshots (
  id TEXT PRIMARY KEY, final_url TEXT NOT NULL, title TEXT NOT NULL,
  html TEXT NOT NULL, captured_at INTEGER NOT NULL,
  content_hash TEXT NOT NULL, byte_length INTEGER NOT NULL
);
CREATE TABLE IF NOT EXISTS web_qa_sessions (
  id TEXT PRIMARY KEY, snapshot_id TEXT NOT NULL UNIQUE,
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL,
  FOREIGN KEY (snapshot_id) REFERENCES web_snapshots(id) ON DELETE CASCADE
);
CREATE TABLE IF NOT EXISTS web_qa_messages (
  id TEXT PRIMARY KEY, session_id TEXT NOT NULL, role TEXT NOT NULL,
  content TEXT NOT NULL, status TEXT NOT NULL, error TEXT NOT NULL DEFAULT '',
  model_id TEXT NOT NULL DEFAULT '', created_at INTEGER NOT NULL,
  FOREIGN KEY (session_id) REFERENCES web_qa_sessions(id) ON DELETE CASCADE
);
```

# 渐进主题索引：首轮验证设计

## 已确认的目标

用户希望 LLM 根据论文内容理解生成概括树，而非照搬目录；利用阅读期间的空闲时间逐步关联证据，查询时定位主题后用 BM25 局部检索。每篇论文接受一次全文 LLM 理解，必须控制 token 和等待时间。首字目标为 5 秒；以固定模型、网络和索引可用条件下的 P95 衡量，是本设计提出的验收口径，不是已实现的保证。

本轮先在 benchmark 中验证假设，不改产品 UI、数据库或默认检索路径，不实现产品后台调度。用户已认可“概括树＋少量初始原文证据”的首次输出，并同意先尝试。完整实现前仍需审核本书面设计及后续实施计划。

## 研究问题

一次全文理解产生的主题描述和证据种子，经过零额外 LLM 调用的本地归属扩展，是否能在相同生成预算下改善检索和回答，并满足查询首字目标？不能预设局部检索优于全局检索，也不能把本地词汇匹配归属称为已验证的语义理解。

## 首轮结构与预算

原文按稳定编号分块，复用 evidenceBlock 的逐页锚点。所有对照使用相同原文块、分词器和上下文物化规则，避免分块差异混淆收益。

一次全文调用输出论文概述及最多 5 个顶层主题，可附一层简短子主题。每个顶层主题提供名称、简短描述、最多 5 个真实存在的原文块 ID 作为证据种子。主题应表达论文特有内容；不机械禁止原文标题，也不强迫模型凑足分支。第一轮局部检索以顶层主题为单位。

初始实验上限设为建树输入 32000 token（包括指令）、输出 2000 token；均为可配置实验参数。调用前按选定模型 tokenizer 或保守上界检查，并记录计数方法；超限不截断后声称通读全文，而是标记不适用并使用全局 BM25。失败不自动重复全文调用。记录实际服务商 usage，估算值单独标识。

以原文、模型端点及标识、提示词版本、分块配置作为缓存身份。重复问题复用建树结果，首轮后台扩展额外 LLM token 为零。

## 渐进证据归属

初始状态保留种子及全局原文索引。后台过程在 benchmark 中用确定性批次模拟：用主题描述和种子原文构造本地词项检索，给其他原文块计算主题匹配程度。块可归属多个主题；低匹配或全零得分保留未归属状态。阈值、候选数和权重均配置化，只在开发集调整，不使用评测问题或答案建立索引。

局部 BM25 使用共享全局语料统计并限制候选范围，避免小主题内 IDF 变化成为隐藏变量。保存每次归属的分数和来源，区分 LLM 种子与本地推定归属。输出种子态、半数块处理态、完成态三个快照；完成表示处理完毕，不表示关系已经语义核验。

## 查询路径

对照实验同时比较两种路由：本地主题匹配；一次简短 LLM 路由。后者只接收问题和紧凑主题描述，返回最多两个主题 ID，输出上限 64 token，不请求解释。模型路由失败或 ID 非法直接回落全局 BM25，不追加修复调用。

默认选一个主题，允许第二主题。先保留原始 query；本轮不增加 LLM 改写、查询扩展或额外重排调用。主题内 BM25 召回后合并、去重，并按同一预算物化原文。无主题、无有效候选、索引尚未完成时采用全局 BM25 退路，并记录实际路径。是否需要更主动的全局补充由漏召回分析决定，不能以未经校准的 LLM 自报置信度保证可靠性。

最终生成上下文上限 4096 token，回答模型和提示词在各组保持一致，流式输出。生成依据为原文；主题描述与推定关系不作为事实证据。计时包含路由、检索、上下文组装及模型首个有效正文输出，不以状态提示或预生成答案充当首字。

## 对照与结果

主要对照：相同分块的全局 BM25；种子态主题局部检索；本地扩展完成态主题局部检索。主题方案分别测试本地和短 LLM 路由。现有 semantic-tree 和 hybrid-rerank 可作为补充参照，必须披露分块、模型和成本差异，不能冒充单变量对照。

先用少量固定样本查看结构、引用和计时是否正确，再扩大独立评测样本。小样本只能验证流程与展示案例，不能据此宣称 P95 达标或质量提升。索引输入仅包含论文，不包含评测问题和标准答案。

记录最终上下文的 evidenceRecall、contextPrecision、contextPageMrr，以及现有答案指标；人工检查代表性回答的引用支持性与条件遗漏。记录主题路由漏召回、跨主题问题、全局退路比例及各成熟度表现。页级命中不等价于句子级证据完整性。

成本分开报告每篇建树输入/输出 token、每问路由与生成 token、缓存命中；延迟报告建树时间、查询各阶段及首字 P50/P95。回答缓存不得用于首字达标测量。复用现有配置和本地凭据，不在文档、日志或提交中暴露密钥。

## 判断与后续边界

若质量没有改善、路由增加漏召回或 5 秒目标无法实现，如实报告，优先检查本地路由、主题归属和模型首字耗时，不默认加多轮 LLM。只有证据支持该方向后，才另行设计产品后台优先级、暂停续做、资源竞争及 UI 状态。

首轮交付包括实验代码、可复现实验配置、生成树及证据快照、带成本和延迟的对照报告；不预先承诺性能改善。实现前形成具体实施计划，由用户选择执行方式。

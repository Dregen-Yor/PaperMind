# PaperMind 网页历史与多会话设计

日期：2026-10-17。状态：待用户审阅书面规格。

## 用户目标

用户主动打开一个 HTTPS 网页后，它出现在历史记录中。以后从历史记录选择该网页，即使原站不可用，也能看到本机缓存的可阅读内容，以及该网页下的多个问答会话。对话留档优先于重现网站原本的视觉效果；问答内容继续保存在 SQLite。

本设计扩展现有[网页问答 MVP](2026-10-17-web-qa-mvp-design.md)。它只修改网页的归档、预览和会话组织；现有完整顶层 DOM 作为模型上下文的基线、8 MiB 采集上限、当前模型调用方式和 PDF 问答流程继续适用。网页目录和摘要不属于本轮范围；未来若加入，应以快照版本为单位保存，避免把旧会话的依据改成新网页内容。

## 进入历史的边界

- 用户在地址栏输入、粘贴并打开 HTTPS URL，或把 HTTPS 链接拖入网页问答页，属于**主动打开**。最终页面加载且采集成功后，立即在 SQLite 创建或更新网页历史条目；不必等首次提问。地址栏仅粘贴、尚未执行打开时不归档。
- 在真实网页预览中点击站内链接、后退、前进、刷新及 SPA 路由变化，只改变当前浏览状态，不自动新增历史条目。浏览到这些页面后，用户可点「保存当前网页」，把当前顶层页面明确加入历史，再创建其问答会话。对未归档页面提问时，界面要求先保存当前网页。
- 历史选择只读取本地缓存，不自动联网或重新采集。用户点「打开原网址」时才加载线上页面；这次操作用于浏览，不静默覆盖已归档版本。用户点「更新缓存」时才对当前在线页面采集并尝试新增版本。
- 页面加载失败、跳转中、非 HTTPS、采集失败或超过现有 8 MiB 上限时不写入一个不可预览的空条目；界面保留 URL、显示具体原因和重试入口。已经存在的历史及会话绝不因此删除。

## 页面、快照和会话

```text
网页（一个规范化的最终 HTTPS URL）
├── 快照版本 1（不可变 HTML + 安全的阅读预览）
│   ├── 问答会话 A → 消息
│   └── 问答会话 B → 消息
└── 快照版本 2（更新缓存后内容变化）
    └── 问答会话 C → 消息
```

`web_pages` 是历史列表的父条目，唯一键是最终 HTTPS URL 的规范化值：用 URL 解析器统一主机大小写、默认端口等形式，去除 `#fragment`，保留路径和查询参数。不同查询参数可能代表不同文章，因此分别列项；重定向按最终 URL 归档。页面标题、初次归档时间、最近主动打开时间存在父条目中。URL 相同的主动再次打开或明确「更新缓存」只更新最近打开时间；若新采集的完整 HTML 的 SHA-256 与此网页已有某版本相同，复用该版本，否则新增不可变版本。网页原始 HTML 可能有动态噪声，因此只在用户主动打开或明确更新时比较，不因后台刷新、历史选择或普通站内导航持续创建版本。

`web_snapshots` 归属一个网页，保留现有 `final_url`、`title`、`html`、`captured_at`、`content_hash`、`byte_length`，增加安全阅读预览的数据。会话通过 `snapshot_id` 引用固定版本；移除 `web_qa_sessions.snapshot_id` 的唯一限制，允许多个会话共享同一版本。提问后的消息和模型标识继续在 `web_qa_messages`。创建会话时就选定当前网页的当前版本，不再等首问才生成快照；空会话可暂不落库，首问以事务创建会话和首条用户消息。继续旧会话始终发送其固定 HTML，不受缓存更新或在线导航影响。

## 缓存预览与安全边界

归档时从已加载的顶层 DOM 同步取得原始 HTML 和阅读内容：标题、标题层级、正文段落、列表、引用及代码块，按页面顺序保存为纯文本块。优先文章主体 `article`／`main`，缺失时回退到页面正文；剔除脚本、样式、导航等非正文内容。阅读提取失败时，回退到安全的正文纯文本；若仍无可读文字，则把采集视作失败并保留当前在线浏览状态。预览最多保留 2,000 个块及 512 KiB UTF-8 文字，超出时在预览末尾标明已截断；完整原始 HTML 仍按现有 8 MiB 上限保存，并继续作为模型问答的固定依据。阅读预览只用于人看，不改变模型输入。

选择历史网页时左栏默认显示缓存的静态阅读预览，标明「本地缓存」、快照时间和原网址。预览由 Vue 文本节点构建，不将保存的 HTML 注入应用 DOM，不执行脚本、样式或外链资源；超链接以纯文本显示。它不承诺还原原站排版、交互、登录态、图片或 iframe。用户可明确选择「打开原网址」切换到现有隔离的在线 `WebContentsView`；断网和原站失效不影响缓存预览与已保存会话。浏览在线版本后，用户可返回缓存视图。窄屏时沿用现有网页／问答单栏切换，切到缓存视图或问答栏须隐藏原生网页视图，避免覆盖应用控件。

首次选择网页父条目时，左栏显示该网页最近采集版本的预览，右栏列出该网页所有会话，按最近活动排序，显示首问摘要、创建／更新时间与快照时间；没有会话时仍显示网页和「新建问答」。选择某会话后，左栏切到它引用的快照阅读预览，右栏显示其消息。选择「新建问答」则使用网页当前选定的缓存版本；若用户正浏览其明确保存的新在线内容，使用刚采集的版本。历史列表和会话列表只传标题、URL、时间、ID、大小等元数据；选中时才读取所需预览和消息，发送问题时才读取该会话固定版本的 HTML，避免每次打开页面就通过 IPC 传递全部历史正文。

## 存储生命周期与兼容性

- 不另存 `.html` 文件。SQLite 保存网页元数据、不可变 HTML 快照、阅读预览和会话消息；同一版本的多个会话只引用一份 HTML。继续执行现有单页 8 MiB 限制，不自动按时间或大小淘汰历史与对话。界面显示缓存大小，删除网页时明确提示将连同其全部版本和会话一起删除；单独删除会话不删除仍可复用的快照。
- 启动迁移在事务中把已有快照按规范化最终 URL 归入网页父条目，保留全部快照、会话、消息 ID、内容、状态与时间；重建会话表以去掉 `snapshot_id UNIQUE`。旧快照的阅读预览可在首次选中时以非执行式解析器生成并保存；迁移不访问原站。迁移可重复启动，失败则回滚，不丢旧记录。
- 备份导出包括网页父条目、全部快照和消息；导入校验 URL、父子引用、哈希、大小和唯一 ID，并在写入前完成验证。仍可导入现有 `version: 1` 备份：若没有网页父条目，则按旧快照 URL 构建父条目；若旧备份没有 `webQa`，按空网页历史处理。清空数据时按外键顺序删除网页相关表。设置页的导出、清空文案明确提到网页缓存和问答。
- 修复现有问答归档边界：一旦快照／会话／问题已经写入成功，后续列表刷新失败、取消或导航不能回滚删除它们。助手消息创建失败时，用户问题仍可重新加载并重试；不要在本地保存未成功时调用模型。中断和失败的助手内容不进入后续模型上下文。

## 验收

1. 主动打开网页后，不提问也能从历史选择它，看到本地缓存；在原站离线时结果相同。单纯点击站内链接不会增加历史条目，明确「保存当前网页」后才增加。
2. 同一 URL 两次主动打开，字节相同则复用快照；内容不同则新增版本。旧会话仍显示并使用旧版本，新会话可使用新版本；同一版本下可开两个以上会话。
3. 历史列表先只读取元数据；选中网页／会话才读取预览和消息，提问时才读取相应 HTML。缓存预览中的脚本、事件处理器和外链资源不会运行或请求网络。
4. 从现有数据库及现有备份迁移后，旧消息、模型、失败状态和快照保持可读；新备份导入导出及清空正确覆盖网页父条目。导入坏数据失败时已有记录不受损。
5. 本地保存或助手消息写入失败、请求取消、列表刷新失败时，不丢已归档会话，并有可操作的重试状态。`npm run typecheck`、`npm test` 和真实 HTTPS 网页手工验收通过。

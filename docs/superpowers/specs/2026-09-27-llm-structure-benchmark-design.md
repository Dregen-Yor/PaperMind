# PDF 目录树与直接证据检索：速度优先的产品验证

日期：2026-09-27

分支：`exp/llm-structure`

状态：按用户要求将 C 从 LLM 结构卡片替换为 PDF 原生目录树；其余速度优先设计保留。尚未实现或运行实验。文件名沿用历史讨论名称。

## 1. 产品问题与优先级

用户明确的排序：**速度最重要，其次准确率**。本实验回答：PaperMind 在直接原文检索之上，增加由 PDF 目录自动建立的树，能否改善产品体验。

决策顺序：先检查回答是否仍可用，再优先比较用户实际等待时间，最后考虑准确率小幅收益、调用成本和实现复杂度。不能为了几个质量分默认增加明显等待；也不能通过快速返回空答案获胜。

关注两个产品时刻：

1. 新论文第一次提问：文本解析、索引等待及后台构建是否影响首次可见回答。
2. 已有论文继续提问：取证耗时、首字等待及完整回答时间。

C 的树由文档自身目录确定，不让 LLM 生成主题、摘要或章节。主比较因而变成“PDF 原生目录结构是否值得参与检索”；它不能继续回答“LLM 生成结构是否有效”。保留分支名，仅为延续本次实验。

## 2. 直接沿用当前 bench

核对依据：`bench/README.md`、`runner/qa.ts`、`runner/passageIndexHook.ts`、`speed/{queryTimeline,metrics,contract,policy}.ts`、`scoring/{qScore,qComparison}.ts`。

现有能力继续使用：

- `npm run bench -- --task qa --speed`，schema 2 / `query-timeline-v2`。
- 真实流式回答；首次可见正文才算首字，reasoning/usage 帧不算。
- TTFT 包含检索、消息组装、排队、网络、重试；不是只计模型生成时间。
- 单题串行，客户端 answer cache 关闭，speed 不续跑 query checkpoint。
- 速度主表七列：Evidence Ready P50/P95、TTFT P50/P95、Full Answer P50/P95、Avg Online Tokens。
- 同一数据集、问题顺序、完成 cohort、模型、endpoint、prompt framing、生成参数、环境身份才允许 speed delta/Q；不放宽比较门禁。
- `answerF1AllQuestions`、拒答、失败账目、现有页级证据指标与 `--judge`。
- 4096 token 检索证据预算与公共 materializer；同一 tokenizer/切段/回答 prompt。
- 现有 full-context 路径作为 Q 的参考；现有离线 `--compare ... --q-config ...`。

本轮必须补上的缺口：现有 QA runner 先等待索引完成再记 query t0，passage hook 还强制等待 stage 3。因此热 TTFT 无法回答“刚导入能不能马上问”，`sectionWeight=0` 也无法测不生成结构的收益。

## 3. 对照组：三个产品方案 + 一个现有参考

| ID | 产品方案 | 检索 | 文档处理 | 主要问题 |
|---|---|---|---|---|
| A lexical | 最快可用 | 原文段落 BM25 | PDF 文本提取 + 切段；不加载向量 | 最简路径是否已经足够 |
| B hybrid-raw | 直接证据检索 | 原文 BM25 + 段落向量 | A + 段落向量 | 默认推荐候选 |
| C hybrid-outline | PDF 目录树增强 | B + 目录标题及父路径先验 | B + 原生目录解析建树 + 目录向量 | 原生目录结构是否值得使用 |
| R full-context | 全文直投参考 | 无检索 | 沿用全文 runner，输入同一 PDF 原文 | 相同协议下计算 Q 的标尺 |

**核心比较 B vs C；A 是速度下限方案；R 只是 Q 参考，不是质量理论上限。** A/B/C 的索引阶段全部零生成式 LLM 请求。旧 LLM 卡片、Jev 与 LLM 逐层路由不进入此轮主比较。

A/B/C 使用相同 PDF 文件及页文本、Passage[]、原文清洗、120/350 切段、邻段策略、排序组装及 4096 证据预算。B/C 固定相同 embedding 模型/revision/dtype/维度。原文已有标题对全部臂可见，不刻意删掉来做弱基线。

### 3.1 PDF 目录的精确定义

本轮“PDF 文档目录”定义为 PDF 内嵌 outline/bookmarks，使用 PDF.js `getOutline()`；命名 destination 先经 `getDestination()`，间接页引用经 `getPageIndex()` 转成 0-based 真实页号。保留原生条目的 title、父子关系、顺序和 destination，不请 LLM 重写或生成树。

印在正文中的目录页、正文标题正则抽取不是此处的原生目录。`bench/src/toc/pdfSections.ts` 属于正文标题推断，不能直接改名当作 getOutline 的实现。本轮不引入这两种替代来源；无内嵌目录明确回落 B。

节点范围按目录开始页与下一个非后代条目的开始页保守构造：包含下一节点开始的边界页，允许同页兄弟和父子重叠；最后节点到末页，父节点范围覆盖自身引导段和子树。仅有页号不足以精确确定节末，记录这是候选范围而非精确节证据。重叠只用于加分，最终证据按原文片段去重。前导页或未被目录覆盖的正文仍参与 B 的全局检索。

目录缺失、空标题、外部链接目标、不可解析 destination、越界或逆序范围均有显式诊断。为保持口径简单：任一不能可靠映射的有效条目使本篇目录增强不可用，整篇回落 B，不静默删除节点后声称完整目录。记录失败/回落原因与原始条目数。

### 3.2 树如何参与检索（用户已确认：本地目录加分）

用户已确认保持 B 的原文混合检索，仅增加本地目录先验，不新增在线 LLM 选章节请求：

1. 把每个节点的“父路径 + 标题”用 B 的同一 embedding 模型编码，一次构建后复用。树只含原文目录，不生成摘要/关键词。
2. 查询时复用本题原文检索所需的查询向量，本地计算节点相关性；层级通过父路径和父节点覆盖范围参与评分。
3. 每个 passage 按其真实页范围关联覆盖节点；取关联节点的最高相似度形成目录排序，避免层级越深重复加分。未覆盖段落没有目录先验，仍保留完整的 BM25/向量候选。
4. 目录排序以与原卡片支路相同的加权 RRF 入口融合，初始权重 0.5；最终仍用同一预算填充和原文组装函数。目录先验是可选第三路，不按目录做硬剪枝。

这验证的是“目录树作为本地检索先验”，不是“层级逐层遍历的独立收益”。LLM 目录路由不在本轮范围内，不能在同名 C 内混用两种路线。

无目录或目录向量构建失败时 C 回落 B，记录 `outlineAvailable`、`outlineUsed`、`outlineFallbackReason`。总体产品表包含回落论文，另外报告同一有有效目录的论文子集上 A/B/C 的配对差值，避免把 C 实际等于 B 的样本误当树的收益。

最终回答只接收选中的原文；目录文本不额外注入回答。来源标签统一使用论文/真实页/段落 ID。A/B 不能生成结构再隐藏，C 也不能调用原有结构卡片生成器。

R 保留当前全文输入口径，不强制裁成 4096；它与检索臂的信息预算不同，是 Q 参考，不是结构消融。每轮用同一 PDF 原文、问题顺序、回答模型和生成协议跑 R。

## 4. 速度指标：用户等待在前，模块耗时用于解释

### 4.1 热查询主表：完全沿用 query-timeline-v2

每臂索引就绪、本地模型初始化完毕后，同题同顺序运行：

| 优先级 | 指标 | 用途 |
|---|---|---|
| 首要 | TTFT P50/P95 | 用户开始看到回答的时间；同时关注常态和长尾 |
| 第二 | Evidence Ready P50/P95 | 检索是否在拖慢首字；不能代替 TTFT |
| 第三 | Full Answer P50/P95 | 避免首字快但完整回答很慢 |
| 辅助 | Avg Online Tokens、完成率、失败/超时数 | 解释网络成本和失败偏差 |

保留现有七个 headline 字段与聚合函数，不另造“热速度得分”。报表突出 TTFT，但六个时间分位数仍来自同一完整 cohort。

A 是有意不用向量，不能沿用“bm25 模式一定是意外降级”的逻辑将其判无效；B/C 的意外向量失败仍明确标记。失败样本不补假时间、不从质量分母消失。

### 4.2 冷首问：本轮必做的轻量补充

新增独立 `cold-first-query-v1` 记录，与现有热 speed 并排报告，**不改 query-timeline-v2 的 t0，不把冷时间塞进现有 Q**。

固定起点：用户问题已提交、原文尚未建立索引时，单调时钟开始。主实验全部从真实 PDF 的本地 bytes 开始，包含实际解析；QASPER 文本回归另列，不与 PDF 冷表混排。本轮不开发新 OCR 能力；不能解析的 PDF 如实失败。

每篇使用清单中固定的第一道问题，每个场景最多一次首次提问；所有臂选同一道。记录：

- `localModelInitMs`：需要的本地模型首次进程加载；已经下载好的文件不代表已经初始化。
- `lexicalReadyMs`：本地切段并具备检索条件。
- `denseReadyMs` / `structureReadyMs`：对应能力实际完成，A 无此步骤记不适用，不记缺失错误。
- `coldFirstTtftMs` / `coldFirstFullAnswerMs`：从冷 t0 到首字/完成，直接实测。
- 首问实际使用的 index stage、retrievalMode、结构是否已就绪、后台任务起止与总耗时。

必须区分两种固定策略：

**ready-before-query（索引完全就绪后回答）**：A 等本地切段，B 等段落向量，C 等原生目录建树和目录向量；目录不可用时只等 B。量化等待各完整方案的成本，不声称这就是当前产品的默认首问等待。

**ask-at-lexical-ready（产品首问主场景）**：所有臂本地切段后即回答。A 无后续构建；B 继续向量构建；C 继续段落向量、目录解析及目录向量构建。按产品语义只取提问开始时可见的已落盘阶段快照，不能在回答中途切换索引。模型未就绪则使用 BM25，绝不等待加载。真实后台任务必须继续运行并观测资源/网络争用，不能提前关掉后声称没有影响。

当前产品已有第二种策略的阶段就绪机制，C 在实验中沿用：如果 B/C 首问实际都走 BM25，这正是产品事实，不能给 C 使用尚未就绪的目录先验。此时差异可能来自后台资源争用，也可能几乎没有差异，不预设“取消结构必然让首问更快”。完整索引就绪后的收益由热表测量。

每个策略/臂使用独立 fresh process 和文档缓存未命中条件；模型权重已下载，进程加载成本计入冷时间。清理仅限该实验专用缓存 namespace。首问完成后等待本篇后台任务收尾并记账，再开启下一篇，防止跨论文干扰；收尾不计入已经结束的用户首问时间。

冷表报告 P50/P95、样本数、完成/失败数及场景身份；同一策略、同一输入类型、同一问题清单和完成 cohort 才作差。不能相加“建索引 P50 + 热 TTFT P50”冒充冷首问分位数。

## 5. 准确率：用现有质量指标守底线

主质量直接用现有 `answerF1AllQuestions`：同一版本化参考、全题固定分母、失败/跳过为 0。不新建 semantic judge rubric、span-level evidence 评测或全量人工标注系统。

同时保留：

- 现有 unanswerableAccuracy 与方法标签、回答完成率、索引/生成失败数。
- 现有 evidenceRecall / hit / contextPrecision / contextPageMrr；它们用来定位漏证据，不代替答案质量，也不用于产品排名。
- F1 明显下降或与直观答案冲突的逐题样本，抽查原文、参考答案和回答。必要时复用现有 `--judge`，其耗时不进入回答时间线。

初始回归警戒线仍为：相对 C，候选全题 F1 下降超过 0.02（绝对值）即触发逐题复核，不自动推荐默认替换。该警戒线用于复核，不是非劣证明；复核若发现关键事实错误，即使整体 F1 在警戒线内也不能靠速度分掩盖。

本轮先给产品决策证据，不要求先完成统计非劣证明。重复结果波动大时明确“暂不能定”，不把未显著差异表述成等效。

## 6. Q：复用公式，显式表达速度优先

现有默认配置 `q-score.json` 为 F1 0.6、TTFT P50 0.2、TTFT P95 0.2，偏质量。保留原配置和原公式，历史口径不动。

新增拟用配置 `bench/configs/scoring/q-speed-first.json`：

```json
{
  "schemaVersion": 1,
  "formula": "weighted-geometric-relative-v1",
  "baselineMode": "full-context",
  "weights": { "answerF1": 0.2, "ttftP50": 0.4, "ttftP95": 0.4 }
}
```

此速度优先权重沿用已讨论方案，正式运行前固定并随结果存档，不能看结果后再调。两套权重都用现有离线比较器计算，分别标 `Q_default` / `Q_speed`，不可把新旧分数混作同一口径。

`Q_speed = 100 × (F/Fref)^0.2 × (T50ref/T50)^0.4 × (T95ref/T95)^0.4`

R 为同轮全文参考。Q_speed 用于概括热查询表现，权重不是字典序的速度保证；质量警戒、失败和冷首问必须单独展示，不能用高 Q 抵消明显的产品回归。只有通过现有 qComparison 全部身份/cohort/质量校验后才给分，缺失则显示不可比较及原因。

当前 `qaQuality.ts` / `qComparison.ts` 将质量定义及 source 限定为 QASPER，**现有比较器尚不能直接给真实 PDF 小集计算 Q**。实现时增加显式 `pdf-qa-all-questions-v1` 质量协议，复用现有 token F1 算法、全题固定分母和 Q 公式；PDF 的参考答案来自已冻结人工标注。比较双方必须同 source/质量协议/原文及题集身份，旧 QASPER 路径及拒绝规则保留，新增跨协议拒绝测试。不能给 PDF 假标 qasper，也不能直接移除 source 检查。PDF 协议完成前仅展示热七指标和逐题质量，不伪造 Q。

不为冷启动发明第二套综合公式。报告固定三张表：冷首问；现有热 speed + F1 + Q；文档构建成本。用户可以直接看去掉结构到底省在哪里。

## 7. 数据与运行规模：目录来源决定了主表必须用真实 PDF

`qasper-current.jsonl` 的 60 篇 / 179 题使用 3000 字符伪页，未提供对应 PDF；它不能拿真实目录页号作为证据下标。QASPER 自带 section labels 也不是 PDF 目录。因此原先 A/B/C 都直接跑这份文件的安排必须调整，这是更换 C 的必要影响。

**主产品实验**从现有 `bench/minibatch/annotations.json` 的 3 篇真实 PDF / 12 题开始（Attention、Deep Sets、BERT）；已有真实页证据与答案，先做目录预检并冻结 PDF SHA/提取文本/问题/答案/证据/outline 身份。不得仅挑有目录的论文；没有目录的样本用于验证真实产品覆盖率与回落。目录预检不看方法答题结果。

这 12 题是可启动的产品 pilot，不足以证明普遍优势；尤其不能从极小样本 P95 宣称稳定长尾收益。先得到逐题延迟和重复结果，若要切默认，再补一个预先冻结的小批真实 PDF 标注集，覆盖有/无目录、长短论文。没有 QA 标注的现有长 PDF 仅测解析/冷启动，不计算质量或 Q；不让临时生成的 QA 伪装成人工金标。

**既有回归表**可继续用 QASPER 60 篇跑 A/B/R，以守住原速度/F1/Q 链路；C 在此不具备目录输入，标为不适用，不静默用 section labels 替代，也不把完全回落 B 的 C 当独立结果。该回归表不承担 B−C 的主结论。

同轮固定：PDF 与提取文本 SHA、目录 JSON/解析版本、真实页映射版本、问题顺序、Git SHA、模型及 endpoint、embedding/tokenizer 实际版本、4096 证据预算、相同机器/backend。PDF 页码与 QASPER 页映射有不同身份，禁止跨表做检索 delta。tokenizer main 额外记录本地文件 hash，文件不同即不可比。

分三步运行：

1. **预检/冒烟**：3 篇已标注 PDF 验证 A/B/C 索引阶段零 LLM、目录映射/无目录回落、PDF 质量协议、冷热计时。没有可用目录时明确阻止“目录有效性”结论，先补有目录且已标注样本。
2. **一轮 pilot**：A/B/C/R 各 12 题，共 48 个回答逻辑请求；冷首问每篇固定首题，3 臂 × 2 策略 × 3 篇 = 18 个请求。都不含重试。共享一遍 speed 回答计算 F1，数据增大后数量按实际 manifest 推导。
3. **确认趋势**：B/C/R 再跑两轮，A 若有产品潜力也加入；冷差异用于推荐时也复跑对应策略。固定题序、轮换臂顺序、单臂串行。逐轮计算 speed/Q，不能合并结果绕过 cohort 校验。小样本仍显示每题时间和范围，不把重复当更多独立论文。

temperature、输出上限、thinking、retry、timeout 沿用现有 QA 设置且各臂相同，不通过答案长度或重试差异制造提速。不扫树深度或权重网格，不引入多个路由模型。

热实验可以复用固定目录树和文档向量；冷实验从专用文档缓存 miss 开始，不复用答案/查询向量响应。A/B/C 各自只打开 PDF 一次完成其需要的提取：C 从同一 PDF handle 额外读取目录，避免人为多次解析导致成本失真。本地安装下载时间另列。

## 8. 产品判定

优先看 ask-at-lexical-ready 的冷首问与热 TTFT，再看 Evidence Ready、Full Answer 和 F1。

| 结果 | 产品倾向 |
|---|---|
| B 的冷热速度更好，质量无明显回归 | 默认直接 hybrid 检索，不默认启用目录树增强 |
| A 更快且质量也够用 | A 作为即时可用路径；向量是否值得后台补齐由 B−A 决定 |
| B/C 首问、热查询近似，C 仅多消耗后台构建且质量无实质改善 | 不启用目录树先验；收益叫简化/节约，不夸大为响应加速 |
| C 有质量收益，但显著拖慢响应 | 默认保持快速路径，将结构作为可选深度增强 |
| C 质量明显更好，且冷热响应不退化 | 可以使用本地目录增强，但仍不阻塞首问 |
| F1 降幅大、失败率异常或速度波动改变胜负 | 先复核/复跑，暂不切默认 |

不设置“结构必须提升准确率才算实验成功”的目标。实验成功是清楚回答用户等待发生在哪里，以及哪条路径更适合默认产品体验。

## 9. 最小实现框架：扩展现有 bench，不建平行系统

### 9.1 配置与隔离

在现有 passage 配置保留缺省的 legacy LLM 卡片行为，新增实验 mode `lexical`、`hybrid-raw`、`hybrid-outline`；不把旧 `hybrid-llm` 配置偷偷解释成目录树。验证器按 mode 校验输入：hybrid-outline 必须声明 PDF 输入/解析结果，目录缺失是合法回落，根本没有 PDF 输入则是配置错误。

拟新增 `bench/configs/structure-lexical.json`、`structure-hybrid-raw.json`、`structure-hybrid-outline.json`。mode 经 `types.ts`、`config.ts`、矩阵展开、CLI、hook 全程透传，目录解析版本与 PDF SHA 进入实验 meta/cache identity。

### 9.2 PDF 解析与索引

新增 `bench/src/toc/pdfOutline.ts`，使用 PDF.js 原生目录 API 构造节点和真实页范围；不能用现有 `pdfSections.ts` 的正文正则替代。共享 PDF 文本提取实现，允许从同一个 document handle 获取 pages 与 outline，A/B/R 不承担 C 专属目录向量成本。共用解析流程的调整保持原 `extractPages` 返回行为不变。

`passageIndexBuilder.ts` 增加显式关闭生成式卡片的构建策略，默认保持旧产品行为；A/B/C 均关闭生成，C 在 bench hook 中额外挂只读目录索引。A 为真实 stage 1，B 为 stage 2，C 的目录就绪是独立 metadata/readiness，不把目录树伪装成“LLM 卡片 stage 3”。不修改 SQLite schema 或产品索引序列化语义。

复用 `TocNode` 的 title/path/children/pages 形状，但本轮不调用其 Jev 遍历器。原生目录保留 occurrence ID，可合法同名和同页；不能直接套用 QASPER 构建器的重复路径合并/连续性限制。

`passageIndexHook.ts` 按 mode 返回索引，A/B/C 不再要求 LLM cards。C 目录/目录向量失败回落 B，目录失败理由使用独立字段；不记成结构 LLM 失败、不产生伪 LLM tokens。

### 9.3 检索、热查询与 Q

为 `passageRetrieval.ts` 增加可选且显式的目录先验输入，提取“目录节点相关性 → 段落排名”的小型纯函数；复用现有 RRF/预算填充/原文组装，禁止另写一套排序管线。没有目录支路时 B 行为必须逐字不变，旧卡片支路保持兼容；同一实验不得同时启用卡片与目录先验。

`runner/qa.ts` / `ragPipeline` 的可选依赖透传目录输入并标记实际使用；A 的 bm25、B 的 bm25+dense、C 的 hybrid+outline 或预声明 outline-fallback 都合法，不能把无目录论文从总体分母剔除。意外原文向量失败继续标为降级，严格比较门禁保持。

热 `speed/*` 和 Q 数学公式复用。对 `types.ts`、质量汇总与 `qComparison.ts` 增加显式 PDF QA 协议支持，保持 QASPER 历史路径、全题分母、结果重算与身份门禁；这是 PDF 输入切换必要的适配，不新增质量指标。

### 9.4 冷首问扩展

新增一个小的 `bench/src/runner/coldFirstQuery.ts` 与 `bench/src/metrics/coldFirstQuery.ts`，复用同一构建器、生产检索与流式生成，不复制排序或回答逻辑。以构建器的 stage persist/onStage 事件记录能力就绪，外层时钟贯穿加载/构建/检索/回答。

ask-at-lexical-ready 使用 readiness handle，不能 await 构建 rest 后再声称是即时首问。记录任务完成/失败并做收尾；测试用受控 promise 验证问题在结构完成前已开始回答。

通过现有 bench CLI 增加独立冷场景入口参数（拟用 `--cold-first-query` 与策略选项）；与 `--speed` 互斥，输出独立冷场景 JSON，不传进现有 Q。fresh process/专用缓存由简单批次脚本编排，不新增 structureStudy 框架、裁判服务或 artifact 子系统。

### 9.5 必要测试

- A/B/C 索引阶段均不发生成式 LLM 请求；A 不加载 embedding；旧 LLM 卡片配置行为不变。
- mode 经配置展开/CLI/hook 真正生效；旧配置默认行为不变。
- B 与“C 移除目录先验”最终原文 context 相同；目录标题不额外泄漏进 answer prompt。
- 原生命名 destination、间接页引用、同页兄弟、父节引导段、重名节点、前导页、缺目录/非法目录及回落均有测试。
- 无目录回落 B 不丢题，不伪造 LLM 费用；无 PDF 输入与目录缺失不能混同。
- A/B 的合法检索模式不会被误判为失败；意外降级仍可见。
- 冷计时含真实等待；即时首问不等 rest；后台争用场景真实执行；结束后不会污染下一篇。
- 热 v2 七指标、完整 cohort、F1 固定分母、Q 门禁及 token 完整性保持；新增 PDF 同协议比较通过和 PDF/QASPER 跨协议比较拒绝测试。

完成实现后运行相关新测试、`npm test`、`npm run typecheck`；正式模型实验单独记录，单测通过不能代替产品表现验证。

## 10. 交付结果

一份摘要足够回答默认策略：

1. 冷首问 P50/P95、实际检索模式与失败数（按策略/输入类型分表）。
2. 现有热 speed 七指标 + F1 + Q_default/Q_speed，各轮并列。
3. 目录解析/建树/向量耗时、目录可用率/使用率/回落原因、后台完成时间；明确索引阶段生成式 LLM 调用为 0。
4. B−C 和 A−B 的产品解释、质量回归样本，以及是否值得默认启用 PDF 目录树增强；分别展示全体和目录有效子集。

保留未见数据确认与必要错误分析，不再把多因素机制消融、新证据指标、全量新裁判或大规模统计研究作为首轮完成条件。

# QASPER PageIndex-style 目录树检索对照组设计

日期：2026-09-30

分支：`exp/llm-structure`

状态：已审阅并确认；本文件不实施代码变更。

## 1. 目标

在现有本地 PDF QASPER benchmark 的 A/B/C/R 基础上新增 D 组，用来回答一个独立问题：让语言模型根据论文目录树推理并选择章节，是否比 BM25、混合 passage 检索和目录向量加权更有效。

D 借鉴 PageIndex 的“文档树 + LLM 节点选择”思路。[官方公开的基础树检索](https://docs.pageindex.ai/tutorials/tree-search/llm)同样把问题与文档树交给 LLM，并要求返回相关节点；其生产检索还包含[混合价值搜索](https://docs.pageindex.ai/tutorials/tree-search/hybrid)及未公开细节。因此本组必须命名为 **PageIndex-style TOC tree**，不得称为官方 PageIndex 复现或使用其公开效果作为本实验预期。

本设计是 [本地 PDF QASPER benchmark 设计](2026-09-28-local-pdf-qasper-benchmark-design.md) 的增量规范。未在本文修改的 dataset、PDF 来源、官方评分、证据适配、失败分母、计时与结果持久化规则继续生效。

## 2. 已确认范围

用户已确认以下决策：

1. 新增独立的 D 组，而不是在 B 上叠加树路由。
2. 树只能由 PDF 的目录信息自动推理和梳理出来。
3. 优先使用 PDF 原生书签目录；没有原生书签时，从目录页或正文中的章节标题提取目录。
4. 正文普通段落不得用于建树、补写目录节点或生成节点摘要。
5. 继续使用 AnswerF1、EvidenceF1、retrieval latency P50/P95、TTFT P50/P95，不增加其他正式指标。

## 3. 实验组定义

| 方法 | 查询阶段的检索行为 | 回答上下文 |
|---|---|---|
| A | passage BM25 | 预算内 PDF 原文 |
| B | BM25 + passage dense | 预算内 PDF 原文 |
| C | B + 原生目录标题向量先验 | 预算内 PDF 原文 |
| D | LLM 阅读标题目录树并选择节点；不运行 BM25 或向量检索 | 选中节点对应的预算内 PDF 原文 |
| R | 全文直投参考组 | 完整 PDF 解析文本 |

C 与 D 的差异必须在报告中写明。C 把目录标题的向量相似度作为 passage 排名中的固定权重；D 让 LLM 看到整棵标题树，基于问题推理应读取哪些节点。D 的树没有正文摘要，因此结果不能归因于摘要语义。

D 不依赖 embedding 模型。D 与其他组使用同一回答模型、回答提示词、温度、输出限制、重试策略和 4096-token 检索上下文预算。

## 4. 目录树输入边界

### 4.1 允许进入建树流程的信息

建树器只允许接收以下信息：

- PDF 原生 outline/bookmark 的标题、父子关系和目标页；
- PDF 目录页中的条目标题、缩进、编号、点线和印刷页码；
- 正文页面中被版式或标题规则识别为章节标题的单行文字、物理页码、字号、字重、坐标和编号前缀；
- PDF 总页数，以及用于把印刷页码校准到物理页码的标题匹配结果。

建树器不得接收普通正文段落、QASPER `full_text`、问题、答案、gold evidence 或 canonical 对齐结果。扫描正文页面寻找章节标题是允许的，但只有标题候选及其版式元数据可以离开抽取层。

### 4.2 禁止的树内容

节点只包含稳定 ID、标题、层级、起止物理页、来源和子节点。节点不得包含：

- 根据正文生成的摘要、关键词或假设性标题；
- embedding 或正文相关性分数；
- 问题相关的动态注释；
- 从 QASPER 标注或官方 JSON 复制的 section name。

树根可以使用固定的结构标签 `Document`，但不可作为可检索节点。除该根节点外，不创建没有目录或标题依据的虚拟章节。

## 5. 自动建树规则

建树采用确定性的来源优先级，避免为同一篇论文混合多套目录后产生重复节点：

1. **原生书签。** 原生 outline 可解析、至少包含两个有效目标并覆盖两个不同页面时，保留其标题与父子关系，直接作为结构来源。
2. **目录页。** 否则识别带 `Contents`、`Table of Contents` 等标题的页面，解析目录条目，并通过正文标题匹配校准印刷页码与 PDF 物理页码。只有标题和页码均能验证的条目进入树。
3. **正文标题。** 目录页仍无法形成有效树时，从全文逐页抽取章节标题行，根据编号前缀、字号层级、字重、纵向位置和跨页重复情况推断层级与页码。

层级首先服从原生父子关系或明确编号，例如 `2.1` 属于 `2`。没有编号时使用目录缩进和字号等级；信号冲突时选择较浅层级，不能利用正文含义猜测父子关系。连续页重复的 running header、图表 caption、页眉页脚和参考文献条目必须过滤。

每个节点的起始页是标题目标页。结束页是下一个同级或更高层级节点的前一页；最后一个节点延伸到文档末页。首个顶层节点的读取范围向前延伸到第 1 页，以覆盖目录未列出的标题页和摘要，但不额外生成虚拟节点。父节点范围覆盖其所有后代，顶层节点范围共同覆盖整篇文档。重叠范围只在上下文组装时去重，不能重复消耗预算。

有效树必须满足：至少两个可选择节点；ID 唯一且顺序稳定；页码位于 PDF 范围内；父节点完全覆盖子节点；按文档顺序遍历时起始页不倒退。无法满足时，该论文的 D 索引失败，不回退到 B、C 或全文。

树构建在 query 计时前完成。树、来源类型、构建规则版本和输入 PDF 指纹写入运行产物，以便离线审计。建树不调用生成式 LLM，从而保证树确实只由目录/标题与版式规则生成，并避免把离线模型知识混入对照。

## 6. D 组查询流程

查询时，目录选择模型只接收：当前问题，以及完整目录树的节点 ID、缩进标题和物理页码范围。它看不到正文、节点摘要、BM25 结果、向量分数或 gold。

模型返回严格 JSON：

```json
{
  "reasoning": "brief routing rationale",
  "node_ids": ["2.1", "4"]
}
```

`node_ids` 按相关性排序，最多三个，必须来自给定树。父节点被选中时直接读取父节点的完整页范围，不强制展开为叶节点；同时选择祖先与后代时只保留更具体的后代。重复节点与重叠页范围去重，但保留模型给出的相关性顺序。

节点选择成功后，按相关性顺序读取各节点内的 PDF 原文；节点内部严格按文档顺序装入上下文。不进行 passage 相关性重排，不调用 BM25、dense embedding 或 C 的 outline RRF。达到 4096 tokens 后停止，最后一个范围按现有可追踪的 token 预算规则裁剪。

如果单个叶节点自身超过预算，D 只读取该节点从开头开始能够容纳的原文。这是标题树在没有正文摘要或节点内检索时的明确限制，结果报告不得隐藏。后续若要研究节点内二次检索，应新增另一组，不能悄悄改变 D。

目录选择请求失败、JSON 无效、返回未知节点或空节点列表时，按现有网络重试策略重试；最终仍无效则本题 D 检索失败。不得默认选择第一节，也不得回退其他方法。原始选择输出、解析后的节点、最终页范围和错误原因写入逐题诊断记录。

## 7. 模型与提示词隔离

首轮实验使用 SQLite 中用户指定的 `ds` 配置同时承担 D 的目录选择和所有组的回答，以保持 provider 与模型身份一致。目录选择与回答是两次独立请求：前者只产出节点 ID，后者沿用现有统一回答提示词。

目录选择提示词、JSON schema、最大节点数和模型参数进入 config hash。正式 179 题运行前在 train mini-batch 上冻结；不得根据 dev 的 AnswerF1 或 EvidenceF1 修改提示词。

树选择的 `reasoning` 只作审计，不交给回答模型，也不参与评分。若服务端提供隐藏 reasoning token，它既不构成 TTFT，也不能被解析为节点选择结果。

## 8. 计时口径

D 的 `t0` 与 A/B/C 相同：收到当前问题且尚未发起目录选择请求。D 的 `tContextReady` 是节点选择完成、节点展开和去重完成、原文读取与 4096-token 裁剪完成、最终 trace 固定的时刻。

因此：

```text
D retrieval latency
= 目录选择模型完整耗时
+ JSON 校验与节点展开
+ 原文范围去重、装配和裁剪
```

D 的 TTFT 仍为 `tFirstAnswerToken - t0`，包含目录选择、上下文组装、回答请求网络等待和实际重试。PDF 解析、标题候选提取和目录建树在计时前完成，不计入 retrieval latency 或 TTFT。

A/B/C/D/R 同跑时，速度继续使用所有方法均完整成功的共同问题集合。D 的远程检索调用可能显著提高 P50/P95，也可能因失败缩小共同集合，因此报告必须显示速度 cohort 数量与 hash；不能拿 D 自身成功集合与旧 A/B/C 的共同集合直接比较。

## 9. EvidenceF1 与回答质量

D 的 `predicted_evidence` 只从实际送给回答模型的 PDF 原文 trace 导出，继续执行 canonical PDF v2 对齐和官方 QASPER EvidenceF1。目录标题、树节点和模型 routing rationale 都不是预测证据。

质量分母保持冻结的全部问题。D 检索失败时 AnswerF1 和 EvidenceF1 均按缺失预测计 0；D 检索成功而回答生成失败时保留真实 predicted evidence，AnswerF1 为 0。不得排除无目录、建树失败或超长章节题目来提高分数。

正式报表仍只有六个标量指标。树来源分布、节点选择、超预算裁剪和失败原因属于审计信息，可以写在表外说明或原始产物中，但不能增加新的正式指标列。

## 10. 产物与接口变化

实现需要扩展以下边界：

- PDF 抽取层：保留标题候选所需的行级版式元数据，同时维持当前页面纯文本输出不变；
- 目录树模块：独立负责候选提取、来源优先级、层级推断、页范围计算、校验与序列化；
- benchmark 方法协议：`Method` 增加 `D`，D 的 `retrieve(question)` 能调用目录选择模型并返回最终原文与 trace；
- runtime：向 D 注入受身份记录约束的目录选择客户端，不为 D 初始化 embedding；
- artifacts：保存每篇 D tree 和逐题 routing 诊断，并把 tree builder/prompt 版本纳入运行身份；
- CLI、contract、report、scoring 与 timing：接受 A/B/C/D/R，同时维持六指标 schema。

树 artifact 不得含整篇正文副本；节点只存标题和页范围，正文仍从已冻结 corpus 读取。目录选择原始输出可以随本地运行结果保存，但不得提交真实模型结果、用户 PDF 或凭据。

现有产品 `src/utils/pageIndex.ts` 生成正文摘要并在错误时选择第一节点，与本实验约束不同，不能直接复用为 D。可以复用其无副作用的页范围或 trace 工具，但 D 的树协议和失败语义必须位于 benchmark 专用模块中，避免改变产品聊天行为。

## 11. 验证策略

实施时先写测试，再写生产代码，至少覆盖：

1. 原生嵌套书签生成稳定树；原生书签有效时不混入 fallback 标题。
2. 无书签 PDF 从目录页恢复层级并校准物理页；目录页不可用时从正文标题行恢复。
3. 普通正文、caption、running header、QASPER section name、问题和 gold 不能进入树。
4. 编号、缩进和字号冲突时采用已规定的浅层级；页范围完整、合法且可复现。
5. 目录选择严格校验未知 ID、空列表、重复、祖先/后代和最大三个节点；父节点读取自身完整范围。
6. 大节点按文档顺序裁剪，重叠页不重复，trace 可逐字复原最终上下文。
7. 受控时钟证明目录选择请求计入 retrieval latency 和 TTFT，离线建树不计入。
8. D 失败不回退且保留固定质量分母；A/B/C/R 行为和旧结果读取不受影响。
9. 报表仍只输出六个指标，A/B/C/D/R 同跑采用同一成功速度 cohort。

完成单元与集成测试后运行 `npm test` 和 `npm run typecheck`。真实请求先使用 train mini-batch 检查树来源、节点选择、EvidenceF1 和速度；确认产物有效后，再使用已经冻结的 60 篇 / 179 题集合运行 A/B/C/D/R 对照。mini-batch 只验证实现，不用于调参后汇报为正式结果。

## 12. 验收标准

该对照组可进入 179 题运行前必须同时满足：

- 每棵 D tree 都可从原生书签、目录页或章节标题候选追溯，且不含正文摘要；
- D 查询阶段没有 BM25、embedding、outline 向量加权或静默 fallback；
- D 的最终上下文完全来自被选目录节点覆盖的 PDF 原文并受 4096-token 限制；
- EvidenceF1 与 AnswerF1 沿用现有官方对齐口径；
- 目录选择完整计入 retrieval latency 与 TTFT；
- train mini-batch、全量测试和 typecheck 通过，失败场景有明确记录；
- 报告把 D 标为 PageIndex-style TOC tree，并明确它不是官方 PageIndex 完整复现。

用户审阅并批准本书面规格后，再编写实施计划；批准本文不等于已经开始模型请求或 179 题正式运行。

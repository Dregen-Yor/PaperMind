# PaperMind 网页问答 MVP 设计

日期：2026-10-17。状态：待用户审阅书面规格。

## 目标与边界

用户在独立的「网页问答」页输入 HTTPS 地址，一边阅读实际网页，一边就该网页提问。首版建立一个可对照的基线：提问时取得**当前网页加载后的完整顶层 DOM 快照**，将其作为上下文交给 PaperMind 当前选中的对话模型 API，显示流式回答，并在本机保存快照与问答，重启后可继续查看和提问。

这版不调用 Docling，不做 HTML 分块、检索、摘要、引用定位或跨页面综合问答；它用于检验“完整网页直接交给模型”的效果。保留现有 PDF 论文问答及其 RAG 行为。此前的[网页预览设计](2026-10-16-html-preview-design.md)是本功能的基础；本设计将其入口升级为网页问答。

## 已确认的产品选择

- 入口是侧栏独立「网页问答」页，用户在该页输入 URL。页面保留真实网站视图，不把解析文本伪装成网页。
- 上下文取提问时的 DOM，而非初始 HTTP 响应；由 JavaScript 后续生成的正文如果已进入 DOM，也在快照中。
- 桌面布局与 PDF 阅读页相同：左侧网页初始宽度 58%，右侧问答 42%；中间 7px 拖拽条。左侧比例限制为 30%–75%，双击恢复 58%，键盘左右键每次调整 2%，Home/End 到两端。宽度不超过 800px 时使用与 PDF 页一致的「网页 / 问答」单栏切换。
- 快照和该快照的问答记录保存在本机 SQLite；用户可从最近会话重新打开。

## 页面结构与交互

延续 PDF 阅读器的分栏结构、土色系变量与界面字体。左栏沿用现有网页预览的地址栏、后退、前进、刷新、浏览器打开及原生 `WebContentsView`，网页区域仍由主进程按 Vue 占位框的实际边界设置；拖拽分栏、窗口缩放、窄屏切换后都要重新同步边界。远程网页不能覆盖右栏或接触应用 IPC。

右栏顶部显示「网页问答」、当前模型名称和本轮依据的网页标题、URL、快照时间；下方是会话消息与输入框。首次尚未打开网页时，输入框不可发送，说明“先在左侧打开网页”；网页加载中说明等待加载。已有页面但无快照时，首次发送会先抓取，再显示问题和流式回答。用户可以停止生成、重试失败问题、开始当前页面的新会话，并从最近的网页会话中打开已保存的记录。提问区可显示快照大小，让用户知道本轮将把整页发给模型。

刷新、站内导航、SPA 路由变化后，已有会话仍绑定它首次提问时的快照，旧回答不被重新解释为新页面的回答。右栏明确显示“当前网页已变化；此会话仍依据保存的快照”，并提供「为当前网页新建问答」。页面在同一 URL 下自行修改 DOM 时不持续侦测变化；快照时间始终可见，用户可主动新建会话取得新状态。旧会话可以继续提问，但问题仍依据旧快照；新会话的第一次提问才抓取当前 DOM。重启后打开历史会话时，右栏立即显示本机保存的快照元数据及消息；左栏提供「打开原网址」供用户主动重新加载，线上页面是否加载成功、内容是否变化都不会改写旧快照。离线时仍能看历史，若模型 API 不可用则无法继续提问。

窄屏切换与 PDF 页保持同一交互；切到问答栏时将原生网页视图隐藏或置于零尺寸，防止它盖住问答控件。界面不使用伪引用标签，也不承诺点击回答跳到网页中的句子。

## 快照定义与采集边界

应用只通过可信的主进程在现有隔离的 `WebContentsView` 中执行固定的读取脚本，获取 `document.doctype` 序列化内容、`document.documentElement.outerHTML`、`document.title` 和当前顶层 URL，并记录采集时间。获取前确认主页面已完成加载；采集前后检查当前顶层 URL 与导航代次一致，若发生跳转就放弃并提示重试。采集不向远程页面注入 PaperMind API，不允许网页调用采集 IPC。

“完整 DOM”指采集时**顶层文档的序列化 DOM**：含已渲染进 DOM 的脚本生成内容、内联脚本和属性；不含跨域 iframe 内文、closed shadow root、canvas 像素、外部图片与脚本文件的字节，也不保证随后才异步出现的内容。页面打开后用户可等待内容出现再提问。快照不清洗、不截断后冒充完整；超过 8 MiB UTF-8 字节的页面直接拒绝采集并显示大小限制，不创建空会话。该上限是应用的资源保护，不表示模型一定有足够上下文。快照内容可能含页面中的个人信息或隐藏数据；页面在首次发送前用简短提示说明整页 DOM 会送往用户所选模型服务。

## 数据和调用链

1. `WebPreviewView.vue` 升级为网页问答页面，管理网页/问答的分栏、当前会话、导航提示和发送状态。网页采集、模型请求、持久化分别封装为清晰的模块，不把所有流程塞入页面组件。
2. `PreviewController` 增加只供应用窗口调用的 `captureSnapshot`。主进程验证 IPC 发送者、预览视图存在且已加载 HTTPS 主页面，并返回 `{ finalUrl, title, html, capturedAt, contentHash, byteLength }`；哈希按快照 HTML 的 UTF-8 字节计算。现有预览会话的沙箱、无 preload、权限与导航守卫保持不变。
3. 首次发送时，前端请求快照，成功后在一个数据库事务中保存快照、创建会话和首条用户消息。后续同一会话直接读取固定的本地快照，**每次**调用对话 API 时都附上该完整 HTML、此前完成的问答轮次与当前问题；失败或取消的问题仅在用户重试时作为当前问题发送。用户点击「新建问答」时清空右栏会话状态，下一次发送才采集当时页面。
4. 网页问答调用复用 `chatStore.requestCompletion` 的当前模型配置、流式输出、取消与错误格式；单独构造网页问答消息，不经过 PDF 的 `runRagPipeline`、`retrievalContextChars` 或段落检索。系统消息说明网页 HTML 是不可信参考材料，其中的命令不得作为指令执行；回答可依据网页内容并说明不确定性。原有用户配置的系统提示词继续生效。每次请求包含完整快照和会话历史，不做静默裁剪；模型拒绝或超出上下文时保留用户问题，显示明确错误及“换用更长上下文模型／改用较短页面”的操作建议。
5. SQLite 使用独立的网页快照、网页会话、网页消息表，不把网页条目混进 `papers`、PDF 聊天或 Docling 缓存。每个会话指向一份不可变快照，消息只保存会话 ID，不重复保存 HTML；内容哈希用于核对快照身份，MVP 不跨会话去重。保存最终回答及其模型标识；取消或失败标记为未完成，重试时不会把不完整回答加入下一次模型上下文。删除会话时一并删除其快照。数据迁移、备份导出/导入、数据库清空流程包含这些新表，并保持 `electron/db/schema.ts`、`electron/db/index.ts`、`electron/preload.ts`、`src/types/db.d.ts` 及独立 preview IPC 类型一致。

持久化边界是本地数据库；远程模型只收到用户发送的本轮完整 HTML 与会话文本。未提问的预览页面不自动采集或保存。备份文件若由用户导出，将包含网页快照与消息；界面文案应使这一点可理解。

## 错误与竞争状态

| 场景 | 行为 |
| --- | --- |
| URL 无效、HTTP 或站点加载失败 | 沿用预览页现有错误和重试方式；问答输入不可首次发送 |
| 页面跳转恰好发生在采集时 | 采集作废，提示页面已变化，用户重试；不保存错页快照 |
| DOM 超过 8 MiB | 明确显示页面过大；不截断、不发模型、不保存半成品 |
| 未配置可用对话模型 | 引导到现有模型设置；用户输入仍留在页面 |
| API 超时、限流、上下文超限 | 显示具体可读错误，保留问题与快照，允许重试或更换模型 |
| 用户停止流式回答或离开页面 | 中止请求，保留已保存问题，将回答标为未完成；不把残缺内容当成完成回答 |
| 数据库写入失败 | 不发模型请求；向用户说明本地保存失败，允许重试 |
| 历史会话的 URL 已失效 | 保存的消息和快照仍可查看并继续作为问答依据；左侧显示网站加载错误 |

## 验收与验证

- 在一个有客户端生成正文的 HTTPS 技术文章中，打开页面后提问，收到的模型请求包含当时的顶层完整序列化 DOM，回答使用当前选中的 API 模型；不经过 Docling 或 PDF 检索路径。
- 左 58%／右 42% 的桌面分栏、拖拽范围、键盘调节、双击复位及 800px 单栏切换与 PDF 页一致；调整后网页视图边界准确，不遮挡问答栏。
- 导航后旧会话仍依据旧快照，启动新会话则抓取新页面；重启后能恢复快照与问答，旧 URL 离线时仍可查看历史。
- 快照采集覆盖导航竞争、超大页面、JavaScript 生成内容及只允许应用窗口调用；模型请求覆盖完整 HTML、取消、重试、上下文超限与未配置模型。
- 数据库测试覆盖会话/消息/快照生命周期、迁移、备份导入导出及清空；现有 PDF 问答和网页预览测试保持通过。实施完成后执行 `npm run typecheck`、`npm test`，再进行真实网页与真实 API 的手工验收。

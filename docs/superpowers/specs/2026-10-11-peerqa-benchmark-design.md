# PeerQA 句子级评测与查询延迟设计

- 日期：2026-10-11
- 状态：用户已确认设计，并授权写施工方案、在当前会话直接实现与验证
- 范围：单篇论文、索引就绪、单轮 QA；检索继续使用现有段落、章节和树策略

## 1. 数据与应用场景

PeerQA 包含 208 篇论文、579 个问题，支持证据检索、可回答性和自由回答评测。
官方提供原文句子、段落位置和句子级 qrels；没有证据或自由回答的题不能假装拥有这些标注。

首版原生 TypeScript 导入作者发布的 `qa.jsonl` 与 `papers.jsonl`。按官方段落组织
文本和标题，并沿用现有 benchmark 的伪页输入，运行产品共享的检索实现。报告明确标记
PeerQA 官方解析文本，不能称为真实 PDF 页或 PDF 解析性能实验。OpenReview 全量文本
可通过作者下载与 GROBID 流程准备，然后用同一导入器导入；发布包的可用文本子集也可运行。

每个原文句子保留 `paper_id/pidx/sidx` 身份、页号、原文以及归一化原文跨度。证据映射
只在离线准备时完成，gold 标注不参与在线召回、排名、片段选择或 prompt。
没有文本的论文、没有证据的题、未映射与歧义证据分别计数；本地数据写入忽略目录。

## 2. 句子检索指标

上下文预算固定为现有 BGE-M3 tokenizer 的 4096 tokens。设 G 为该题标注证据句 ID
集合，C 为最终送入生成模型的上下文完整覆盖的原文句子 ID 集合：

| 字段 | 计算 | 定位 |
| --- | --- | --- |
| sentenceEvidenceRecall | `size(G ∩ C) / size(G)` | 主检索指标 |
| annotatedSentencePrecision | `size(G ∩ C) / size(C)`，C 为空时 0 | 辅助密度指标 |
| allGoldSentenceCoverage | `G ⊆ C ? 1 : 0` | 全部标注证据覆盖诊断 |

逐题计算后取算术均值。All-Gold Coverage 不等于逻辑充分性，未标注句子也可能有用，
Annotated Precision 不代表完整的语义相关性判断。现有页级指标保留作兼容诊断。

最终 token 物化器额外返回实际保留下来的逐页文本片段。评测根据源页与归一化跨度
追踪完整句子，不从候选页、选中章节或物化前文本推断。归一化只处理 Unicode 与排版
空白，保留大小写和标点；不使用语义相似度判断命中。重叠片段的来源区间求并集，重复
句 ID 去重，两个连续片段共同完整覆盖一句也算命中；只留下半句不算命中。
无法唯一溯源的非空片段是评测契约错误，拒绝产出可比较结果，不能默认为未命中。

句子检索有效题集合在运行前冻结：可回答、非空证据、全部证据均明确映射。
索引或检索失败在这组题中写三个零值；生成失败保留已经得到的检索观测。
输出定义版本、语料/标注指纹、句子有效题 ID 哈希与数量、映射覆盖率和指标观测数。
所有指标观测数必须等于有效题数，跨方法身份不一致时不计算差值或标注最优。
全文直投单独报告回答质量和速度，不进入 4096-token 检索排名。

## 3. 回答质量

PeerQA 按原始标注分别冻结回答参考题和可回答性题集合，保存题号和参考答案。
ROUGE-L F1 用作者自由回答作为参考，失败或跳过回答计 0；无参考的题不进入该分母。
Answerability Macro-F1 对可回答、不可回答两类分别计算 F1 后取均值，拒答检测记录
规则版本。失败和跳过不当作拒答，按预测缺失计算该真实类的 FN，不让故障提高分数。
同时展示两类样本数、完成率、回答长度与 judge 有效评分覆盖率。

AlignScore 和 Prometheus 正确性必须来自对应原评测模型，不能用词法 F1 或通用 judge
冒充。提供原生离线评分导入入口，逐条校验题号、当前答案 SHA-256、评分范围和模型
身份，绑定源结果字节 SHA-256；缺失评分记失败观测 0，报告评分覆盖率。Prometheus
1–5 分转换成 `[0,1]` 后再纳入固定分母均值，并保留原始分。未配置这些评分时显示
`—`，附明确原因；共享 `--judge` 的结果继续以现有 judge 名称单列。
模型评分在查询结束之后执行，不影响速度时间线。PeerQA 不生成综合 Q 分。

## 4. 查询延迟

复用 `query-timeline-v2` 的真实流式实现：

```text
t0：开始在线处理问题（索引与本地模型此前就绪）
t1：最终上下文就绪
t2：客户端收到第一个非空回答正文 delta
t3：回答流正常结束、完整非空答案可用
TTFT = t2 - t0
Full Answer = t3 - t0
```

TTFT P50/P95 与 Full Answer P50/P95 使用同一完整成功题集合、同一单调时钟和最近秩
算法。检索、组装消息、排队、网络、重试和退避均包含；建索引、隐藏 reasoning、usage
帧和离线评分不计入。这里是客户端接收时间，未包含 Electron 界面绘制时间。
空集合显示 `—`。报告尝试数、成功数、超时与断流数及比例；失败不能被零毫秒补进分位数。

保持现有 Evidence Ready 与真实 Online Tokens 辅助指标。回答缓存关闭、并发固定为 1，
跨方法继续校验题目 cohort、回答模型/端点、提示词、生成参数、重试与执行环境。
输出词数分布辅助解释 Full Answer；只在 provider 返回真实 usage 时记录 token 数。

## 5. 报告与兼容

PeerQA 报告包含独立的句子检索、回答质量、查询速度表和分母/失败诊断。
命名包含句子定义版本与预算，不能把页级 MRR 改名为句子 MRR。
与 QASPER/smoke 同时运行时按 source 分组；旧结果仍可读取，缺少句子版本者不能参加
句子指标比较。QASPER 现有 Q、页级指标、速度协议与产品检索行为保持兼容。

## 8. 实现中确认的数据情况（2026-10-11）

官方 v1.0 包含 579 道问题，其中 53 道 `answerable: null`。原生导入排除这些未标注问题，并以 `unlabeledQuestions` 单独计数；已标注但缺论文文本的题计入 `missingPaperQuestions`。公开文本子集得到 85 篇 / 194 道已标注问题，不代表完整 PeerQA 切片。空提取内容保留原始顺序，但不产生句子。包内一对公式／图注共用 `(paper_id, pidx, sidx)`，原文保留、歧义身份排除，引用它的问题标记 ambiguous；归一化数据加载时拒绝重复句 ID、越界或重叠跨度。

原生回答口径为 `peerqa-native-rouge-refusal-v1`，复用项目 ROUGE-L 归一化，识别 `No Answer` 和现有拒答模式；它是应用评测口径，不能冒充论文 rouge_score 的复现分数。拒答规则版本变化时回答质量定义同步变化。两类 Macro-F1 使用固定类别集合，失败题只加真实类 FN。
